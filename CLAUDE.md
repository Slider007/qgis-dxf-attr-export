# Плагин QGIS «DXF с атрибутами»

Устройство и возможности — в `README.md`. Общие правила модулей компании — в
`~/Projects/QGIS/CLAUDE.md`.

## Как выпускать версию

1. `tests/run_tests.sh` — все проверки должны пройти.
2. Поднять `version=` и дописать `changelog=` в `dxf_attr_export/metadata.txt`.
3. После подтверждения — коммит и пуш, затем релиз с архивом:
   `gh release create vX.Y.Z "$(./build_zip.sh)" --title X.Y.Z --notes "…"`.
4. Дальнейшие шаги — в локальном `CLAUDE.local.md`.

## Устройство

- `processing/export_dxf.py` — алгоритм `dxfattrexport:exportdxf`. В
  `prepareAlgorithm` (основной поток) слои копируются через `materialize` со
  стилем, в копию добавляется поле `__dxf_attr_key` = `QFX_<n>`. Номер поля
  отдаётся `QgsDxfExport.DxfLayer` как поле имени слоя — так у каждого объекта
  в DXF свой временный слой.
- `dxf_blocks.py` — без QGIS: разбор DXF по парам «код — значение», перенос фигур
  объекта в блок (BLOCK_RECORD + BLOCK с ATTDEF), вставка INSERT + ATTRIB + SEQEND
  на месте первой фигуры, TEXT/MTEXT (подписи) остаются в модели. Базовая точка
  блока = точка вставки, поэтому координаты фигур не пересчитываются.
- Режим «только границы» (`BLOCK_CONTENT=1`): фигуры QGIS объекта выбрасываются,
  в блок пишутся LWPOLYLINE/POINT из `FeatureBlock.shapes`, построенных по
  геометрии в `outline_shapes`; цвет — `outline_color` по символу рендерера.
  Объект, скрытый стилем (`willRenderFeature` = False), не выгружается, как и в
  полном режиме.
- `processing/import_dxf.py` — алгоритм `dxfattrexport:importdxf` (чтение DXF).
  Читает и пишет **GDAL напрямую** (`osgeo.gdal/ogr/osr`), три прохода по файлу:
  `scan` (какие слои получатся и где подписи) → `bindings` (какая подпись чьей
  станет) → `write`. Атрибуты блоков GDAL не отдаёт, поэтому их разбирает
  `dxf_read.py`, а объектам они возвращаются по `EntityHandle` вставки.
- `dxf_read.py` — без QGIS: атрибуты вставок, дескрипторы ATTRIB и TEXT/MTEXT,
  определение кодировки по содержимому, распознавание DWG и двоичного DXF.
- `plugin.py` — две кнопки (выгрузка и импорт) открывают
  `processing.execAlgorithmDialog`; выгрузке передаются включённые векторные слои
  и СК проекта.

## Грабли

- **Кодировка.** QGIS 3 пишет байты в выбранной кодировке (заголовок
  $DWGCODEPAGE ей соответствует), QGIS 4 при том же заголовке пишет UTF-8 —
  читатели DXF показывают такой файл кракозябрами. `dxf_blocks.read_codec`
  распознаёт файл по содержимому, а записывает всегда в объявленной кодировке,
  то есть попутно исправляет файл QGIS 4. В QGIS 4 список `QgsDxfExport.encodings()`
  в нижнем регистре («cp1251»), поиск кодировки — без учёта регистра.
- **Версия DXF.** 3.40 пишет AC1015, 3.44 и 4.2 — AC1018. По версии кодировку
  определять нельзя (см. выше).
- `QgsDxfExport` переносит в DXF только «Простую заливку»: остальные заливки
  дают лишь контур. Штриховку линиями модуль рисует сам (`hatch_lines` —
  линиями, `_hatch_entities` — штриховкой AutoCAD `_USER` с узором в самом файле).

- Папка плагина `dxf_attr_export` — это id у пользователей, не менять.
- `QgsDxfExport` сам пропускает подпись, если в ней есть символ вне кодировки.
- `QgsMapLayer.title()` в 3.40 устарел: заголовок — `serverProperties().title()`.
- Memory-слой в тестах: строковое поле без длины ограничено 255 символами, объект
  с более длинным значением молча не добавляется — задавать `string(1000)`.
- Проверка DXF строгим валидатором: `ezdxf` (`ezdxf.recover.readfile` + `audit`)
  во временном venv вне QGIS; в модуль `ezdxf` не входит.
- Кнопка, пункт меню и панель — общие «Альтан-Эко»: `altan_toolbar.py` и
  `altan_logo.svg` копируются из `~/Projects/QGIS/shared/` без изменений.
- Сборки 3.44+ и 4.x устроены иначе: python в `Contents/MacOS/python3.12`,
  нужен `PYTHONHOME=Contents/Frameworks`, python QGIS в `Contents/Resources/qgis/python`.
  `tests/run_tests.sh` это учитывает; другая версия — `QGIS_APP=…`.
- Проверка в настоящем QGIS: `QGIS --profiles-path <tmp> --code check.py`, плагин
  включается в `<tmp>/profiles/default/qgis.org/QGIS3.ini`. Окно алгоритма модальное:
  закрывать его таймером, найдя через `QApplication.activeModalWidget()`.
  Только **с экраном**: с `QT_QPA_PLATFORM=offscreen` QGIS падает (139) ещё до
  выполнения `--code` — проверено на 3.40 и 3.44 (это общая грабля, см. навык).
  Алгоритмы проверять через `qgis_process` (`scripts/qgis_env.sh --profile`).
  И `print` из `--code` в stdout не попадает: писать в файл.

## Грабли импорта

- **Свой метод не называть как метод Processing.** Внутренний `group()` перекрыл
  `QgsProcessingAlgorithm.group()` — QGIS падает при построении панели
  инструментов (`TypeError: group() missing 5 required positional arguments`), а
  `processing.run` в тестах этого не видит. Ловит `AlgorithmApiTest`: он зовёт все
  методы, которые QGIS дёргает сам, и ищет перекрытые методы Processing
  (выпущено в 1.1.0, исправлено в 1.1.1).

- **Что отдаёт GDAL из DXF.** Один слой `entities` со смешанной геометрией; дуги,
  окружности и сплайны — уже ломаными; штриховка — полигоном (её имя узора лежит
  в поле `Text`, это не подпись); вставка блока — `GEOMETRYCOLLECTION` из фигур
  блока с дескриптором самой вставки. Значения атрибутов приходят отдельными
  подписями **без имён атрибутов** — поэтому их и разбирает `dxf_read`.
- **Настройки GDAL по версиям.** `DXF_CLOSED_LINE_AS_POLYGON` — не параметр
  открытия, а настройка, и в GDAL 3.3.2 (QGIS 3.40) её ещё нет: замыкание
  полилиний делает сам модуль (`as_polygon`), иначе поведение разошлось бы по
  версиям. `DXF_MERGE_BLOCK_GEOMETRIES=FALSE` разбирает вставки на отдельные
  фигуры; `DXF_ENCODING` задаёт кодировку текста.
- **Кодировка чужих DXF.** `dwg2dxf` (LibreDWG) пишет UTF-8, оставляя в заголовке
  ANSI_1251: по заголовку имена слоёв выходят кракозябрами. `dxf_read.detect_encoding`
  смотрит содержимое, но сбои UTF-8 прощает только в файле, где нерусского текста
  много (`MIN_NON_ASCII`): иначе чертёж с тремя русскими буквами в CP1251 будет
  принят за UTF-8. Прочитанное не той кодировкой имя слоя GDAL потом не принимает
  (`TypeError: argument 2 of type 'char const *'`).
- **GeoPackage.** Это SQLite: несколько одновременно открытых `QgsVectorFileWriter`
  на один файл дают «database is locked» — все слои пишутся одним соединением
  `ogr`. Имя таблицы должно начинаться с буквы или подчёркивания, а в чертежах
  встречаются слои «!РКЗ_ВЛ 220 кВ» — имена чистит `layer_name` (эта же грабля
  известна по `temp_layers_to_folder`). СК задавать по
  коду (`SetFromUserInput(crs.authid())`): от `crs.toWkt()` GDAL ругается на
  несовпадение с официальным описанием и заводит свою запись СК.
- **Подклассы не всегда есть.** `SubClasses` (`AcDbText`, `AcDbAttribute`) пишут
  не все программы: подписи и значения атрибутов опознаются по дескрипторам из
  `dxf_read`, а подклассы — только подспорье.
- **DWG.** Читателя нет ни в GDAL сборок QGIS, ни в Python. Внутри QGIS есть
  libdxfrw (знает версии до AC1032), но только в окне «Проект → Импорт/Экспорт →
  Импорт слоёв из DWG/DXF»: привязок к Python у `QgsDwgImporter` нет. Бесплатный
  ODA File Converter встраивать нельзя — по лицензии он только для
  некоммерческого применения. `dwg2dxf` из LibreDWG (GPL-3) ваш AC1032 переводит.
- Параметр файла с фильтром только `*.dxf` отвергает выбранный DWG силами
  Processing («Incorrect parameter value»), и понятное сообщение модуля не
  показывается — в фильтре нужны «Все файлы».
