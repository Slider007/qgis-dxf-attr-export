# DXF с атрибутами — модуль QGIS

Два окна: выгрузка слоёв QGIS в DXF для AutoCAD и чтение чертежей DXF обратно в ГИС.

## Выгрузка в DXF

Сохраняет свойства объектов:

- **атрибуты**: каждый объект записывается блоком с атрибутами. Значения всех
  полей видны в «Свойствах» AutoCAD при выборе объекта и извлекаются в таблицу
  командой ИЗВЛЕЧЬДАННЫЕ (DATAEXTRACTION). По умолчанию атрибуты скрыты на чертеже,
  показать их можно галочкой «Показывать атрибуты на чертеже»;
- **оформление** — на выбор («Оформление в блоках»):
  - *полное оформление QGIS*: цвета, толщины и типы линий, заливки, значки точек
    (как во встроенном экспорте QGIS);
  - *только границы объектов*: полигоны — замкнутыми полилиниями по каждому
    контуру (с дырками), линии — полилиниями, точки — точками AutoCAD. Цвет —
    обводки символа (у полигона без обводки — заливки, у точки — значка);
- **штриховка линиями** — её встроенный экспорт QGIS не переносит вовсе, модуль
  переносит сам: линиями внутри контура (надёжно, файл крупнее) или штриховкой
  AutoCAD (один объект на контур, файл в разы меньше). Можно отключить;
- **подписи** QGIS — текстом на том же слое, что и объект;
- **слои**: слой AutoCAD — имя слоя QGIS или значение поля, выбранного в столбце
  «Output layer attribute» списка слоёв (например, тип опоры);
- **координаты** — в выбранной системе координат, без смещений; рядом с DXF
  пишется файл `.prj` с описанием СК, единицы чертежа — метры. Система координат
  подставляется сама: чертежи AutoCAD почти всегда в МСК, поэтому при открытии
  окна с кнопки модуль определяет МСК того места, которое сейчас на карте, и
  подставляет её (например «МСК-50 зона 2 Московская область»). Если у проекта
  уже задана метровая СК, берётся она — это осознанный выбор. Выбрать другую
  можно в том же поле.

## Импорт DXF

Читает чертёж и раскладывает его по слоям GeoPackage, которые сразу добавляются в
проект:

- **отдельный слой** на каждый слой AutoCAD и вид геометрии: «Границы зон
  (полигоны)», «Дороги (линии)», «Опоры (точки)». Можно собрать всё в один слой
  каждого вида;
- **система координат** уже подставлена — так же, как при выгрузке: МСК места,
  которое сейчас на карте (субъект РФ определяется по OpenStreetMap, набор МСК
  встроен в модуль). В самом DXF системы координат нет, поэтому поле важное: если
  чертёж в другой СК, поменяйте там же. Нет сети или место вне России —
  подставляется СК проекта, об этом говорится в сообщении. Если рядом с чертежом
  лежит `.prj` с другой СК, модуль предупредит;
- **замкнутые полилинии** читаются полигонами (отключаемо);
- **атрибуты блоков** становятся полями таблицы: имена полей — из тегов
  атрибутов (NOMER, ТИП). Встроенное в QGIS открытие DXF так не умеет: оно
  разворачивает блок и превращает значения в отдельные подписи, теряя имена;
- **подписи чертежа** (TEXT, MTEXT) попадают в поле `text` того объекта, внутрь
  которого легли. Подпись достаётся наименьшему из содержащих её контуров;
  объект, собравший больше трёх подписей, не получает ни одной — это не его
  подпись, а чужой текст внутри контура (съёмочные точки внутри большой зоны).
  Непривязанные подписи остаются слоем «Подписи (точки)», так что не теряются;
- **кодировка** определяется по содержимому файла, а не по заголовку: конвертеры
  DWG→DXF часто пишут UTF-8, объявляя CP1251, и тогда имена слоёв у других
  читателей выходят кракозябрами;
- у каждого объекта остаются `dxf_layer`, `entity`, `handle`, `linetype` и
  `block` — по ним видно, откуда он взялся в чертеже.

Модуль предупреждает, если выбрана система координат в градусах, а координаты
чертежа в метрах; если файл пишется во временную папку и потом пропадёт; если
указанный GeoPackage уже существует — тогда заменяются только одноимённые слои,
а чужие остаются нетронутыми.

Кнопка модуля — на панели «Альтан-Эко»: по нажатию открывается список из двух
действий. Те же пункты есть в меню *Модули → Альтан-Эко*, а оба алгоритма — в
панели инструментов Processing.

В окнах на виду только главное; тонкая настройка (кодировка, масштаб, перенос
стилей, высоты) убрана под «Дополнительно», у каждого поля есть подсказка.

Требуется QGIS 3.40 или новее, в том числе QGIS 4.

## Ограничения выгрузки

- Формат — DXF (AutoCAD 2000). DWG не записывается: DXF открывается в AutoCAD
  без потерь, при необходимости его можно сохранить как DWG уже в AutoCAD.
- Значение атрибута — одна строка до 250 символов; более длинные укорачиваются,
  переводы строк заменяются пробелами. О каждом таком случае выводится предупреждение.
- Символы, которых нет в выбранной кодировке (по умолчанию CP1251), в атрибутах
  записываются кодами `\U+XXXX` и в AutoCAD отображаются правильно. Подпись с
  таким символом QGIS при выгрузке пропускает — это поведение встроенного экспорта.
- Объекты без геометрии не выгружаются. Объекты, скрытые стилем слоя (снятая
  галочка у категории), тоже: в DXF попадает то, что видно на карте.
- Заливки, которых нет в DXF, не переносятся: градиент, SVG, растровая,
  точечный узор, по центроиду, случайные значки. Остаётся контур, а модуль
  выводит предупреждение с числом таких объектов.
- Прозрачность слоя и символов в DXF не передаётся: в AutoCAD заливка сплошная.
- Чтобы изменить геометрию в AutoCAD, блок объекта нужно расчленить (РАСЧЛЕНИТЬ /
  EXPLODE) — атрибуты при этом теряются.

## Ограничения импорта

- **DWG не читается.** Ни в GDAL, ни в Python нет читателя DWG. Получить DXF
  можно тремя способами:
  1. **AutoCAD**: «Сохранить как» → DXF. Ничего не теряется, лишних программ не
     нужно.
  2. **LibreDWG** — бесплатная программа GNU (https://www.gnu.org/software/libredwg/),
     разрешена и для коммерческой работы. Перевод делается вручную, модуль её не
     вызывает: `dwg2dxf -o чертёж.dxf чертёж.dwg`, затем открыть полученный DXF.
     Установка: macOS — `brew install libredwg`; Windows — сборки на
     https://github.com/LibreDWG/libredwg/releases. Оговорка: DWG 2004–2018
     LibreDWG читает не полностью, после перевода стоит сверить число объектов.
  3. **Встроенное окно QGIS** «Проект → Импорт/Экспорт → Импорт слоёв из
     DWG/DXF» читает DWG само, но не делает из атрибутов блоков поля таблицы.
- Двоичный DXF не читается — нужен обычный текстовый.
- Дуги, окружности и сплайны приходят ломаными линиями: так их отдаёт GDAL.
- Оформление чертежа (цвета, типы линий, штриховки) в стиль слоя не переносится;
  сами штриховки приходят полигонами.
- Все поля — текстовые: в DXF у атрибутов нет типов.

## Как это устроено

Выгрузку делает встроенный `QgsDxfExport`: он переносит стили и подписи. Для
каждого объекта ему задаётся временное имя слоя DXF. Затем `dxf_blocks.py`
переписывает файл: фигуры объекта переносятся в его собственный блок с описаниями
атрибутов, в пространстве модели остаётся вставка блока со значениями, временные
слои заменяются настоящими.
